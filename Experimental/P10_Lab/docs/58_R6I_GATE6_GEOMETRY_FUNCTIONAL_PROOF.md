# ConceptGhost P10 — R6I Gate 6 Geometry Functional Proof

Date: 2026-09-25
Status: IMPLEMENTATION / CI — TARGET-PC ACCEPTANCE REQUIRED

## Why Gate 6 is reopened

Gate 6 is not considered functionally closed merely because COLMAP, dense
reconstruction and Poisson meshing return successfully.

The Gate contract requires a new 3D reconstruction from the Gate 5 drone/WAN
views. Gate 6 must therefore publish a non-empty, directly inspectable P10
geometry artifact before Gate 7 is allowed to decide whether to accept or
reject any part of it.

The 20260925 target-PC attempt proved that a pre-fusion mesh existed, but that
artifact was not exposed strongly enough as the Gate 6 deliverable and Gate 7
later rejected every P10 face. Runtime success and functional geometry delivery
are now treated as separate acceptance conditions.

## R6I-A — explicit raw P10 geometry output

Gate 6 now publishes:

- `GATE6_RAW_P10_GEOMETRY.ply`
- `GATE6_RAW_P10_GEOMETRY.obj`
- `GATE6_DENSE_POINTS.ply`
- `GATE6_OUTPUT_MANIFEST.json`
- `README_GATE6_OUTPUT.txt`
- `GATE6_P9_P10_OVERLAY.png` when the metric overlay is available.

The raw P10 mesh is generated BEFORE Gate 7 filtering or P9/P10 protected
fusion. Gate 7 can no longer make the Gate 6 geometry artifact disappear.

Gate 6 fails closed when the pre-fusion mesh is missing or empty.

## R6I-B — run-local / P9-run sidecar

For a known P9 source run, a compact inspection copy is also written to:

`<P9_RUN>/P10_GATE6_OUTPUT/<p10_attempt_id>/`

and the P9 run receives:

`LATEST_P10_GATE6_OUTPUT.txt`

This keeps the geometry close to `RUN_AUDIT_BUNDLE.zip` without mutating the
authoritative P9 mesh.

## R6I-C — workflow legibility

Workflow 02 is explicitly divided into visual groups:

- GATE 4 — drone/camera evidence; output = control + camera manifests;
- GATE 5 — new-view generation; output = WAN multiview images;
- GATE 6 — 3D reconstruction; output = raw P10 geometry (.PLY/.OBJ).

The Gate 6 preview node is titled as a Gate 6 OUTPUT and explicitly states that
it is before Gate 7.

## R6I-D — target-PC recovery

The R6I package includes a resume helper that finds the latest existing P10
attempt and reruns/resumes Gate 6 only. Existing Gate 5 WAN images and the Gate 4
camera manifest are reused; WAN is not regenerated by this helper.

This is intended to prove the Gate 6 artifact on the already-computed target-PC
run before spending another full WAN generation cycle.

## Acceptance

Gate 6 functional acceptance requires:

1. dense reconstruction artifact exists;
2. raw P10 mesh exists;
3. raw P10 mesh has >0 vertices and >0 faces;
4. the same geometry is available in PLY and OBJ;
5. Gate 6 output manifest identifies the source P10 attempt;
6. artist can inspect the raw geometry independently of Gate 7;
7. if the geometry is poor or fails to fill intended occlusions, Gate 6 remains
   open for reconstruction-quality refinement even though the raw output exists.

Gate 7 and Gate 8.2 remain blocked until Gate 6 geometry is visually inspected
and the reconstruction-quality issue is understood.
